# 简历项目描述与面试说明

可以将第二项目写成“研发知识库 RAG 问答系统”，在介绍中明确基于开源项目改造。下面是目前有源码和实测支撑的版本。

## 可用项目描述

**研发知识库 RAG 问答系统｜Python、FastAPI、BM25、RRF、Cross-Encoder、SQLite、ONNX**

基于开源 rag-qa-system 改造研发／运维文档问答，接入 20 篇固定版本官方文档及 2 份代码示例，构建含来源、行号与版本的 325 个可追溯片段。

- 实现内容摘要驱动的增量入库与 SQLite 事务版本替换，避免重复计算向量及文档更新后残留旧片段；检索前按服务端身份过滤租户与部门权限。
- 建立 32 题答案段落级标注集，在当前 22 份资料／325 片段上比较纯向量、BM25、混合召回及重排，各重复 3 次；混合重排 MRR@5 为 0.810，纯向量为 0.601，BM25 证据覆盖率最高为 93.75%；记录效果和 CPU 耗时代价。
- 将模型逐字复制引用改为选择编号与服务端还原，补充同一授权快照内的代码及相邻证据；增加正文语言检查和最多一次内容纠正。原七个失败场景各两轮真实回归，14/14 达到预期，并增加十二道中英文、拒答及权限验证题。
- 实现执行容量限制及上游超时/限流错误分类；加入人工评分来源冻结和原子持久化，通过 76 项离线边界与接口测试，覆盖越权、版本替换、伪造引用、语言错误、并发参数隔离及故障后的执行名额释放。
- 完成 50 题真实生成配置下的端到端评测及 6 道相近领域拒答题，保存实际模型消耗与失败记录；运行 1/2/4 并发实验，12 次真实生成热请求无运行失败，4 并发 P95 为 3.75 秒。
- 完成 Linux ARM64 容器实际构建与九项检查，通过持久卷保存原文、版本和模型缓存，验证容器重建后文档仍可读取与检索。

已使用 DeepSeek 运行真实评测；RAG 页面默认仍为资料摘录模式。历史主评测由助手按证据逐题复核，完整任务通过 43/50；修复后已重跑原 50 题，39 个回答、11 个拒答、运行错误 0，自动状态／权限检查 50/50。作者本人逐题人工评分正在准备／填写，最终分数以真实记录为准，第三方独立评分未完成。不能把自动检查当作语义准确率，不写“整体准确率 100%”“幻觉降低 XX%”或“企业生产落地”。

## 面试时必须主动说明的数据边界

32 条独立问题来自人工整理的英文开发集，不是盲测。384 次运行是 32 × 4 × 3，不能当作 384 条独立数据。

BM25 的证据覆盖率为 93.75%，高于混合重排的 89.06%；重排胜在首个正确片段排名。MRR 的提升是方案对照，混合检索与重排算法来自上游，自己的贡献是工程边界、修复、标注与可复现测量。

当前模型基于英文、资料规模小、数据均公开；权限分类是模拟的，性能来自本机热模型 CPU，没有企业用户数、线上 SLA 或公网容灾验证。本次检索和生成全量程序有重叠，不能把这轮耗时视为隔离性能基准。中文审核译文不等于重新验证了中文查询效果。

真实生成的每档并发只有四条热请求，0/12 失败仅代表这一轮观测。50 题并不全都调用了模型：无证据时应用先拒答，主集 39 次、相近主题补充集 6 次收到真实 API usage。引用存在与语义支持需要分别检查；细节见 validation-results.md。

## 值得掌握的追问

| 问题 | 应解释的实现 |
|---|---|
| 为什么保存原文之外还要存 revision？ | 内容、权限、模型与分块配置共同决定版本，更新后片段必须和原文一致 |
| 文档更新到一半失败怎么办？ | 先完成向量计算，再事务替换；失败回滚并保留旧版 |
| 两个管理员同时更新会怎样？ | 写事务里再次校验旧 revision，冲突请求拒绝覆盖更新 |
| 为什么权限不能只放到 Prompt？ | 模型看到资料就已经泄露；SQL 快照先筛选后才召回、重排与生成 |
| 为什么只展示真实使用的引用？ | 候选材料不一定支持答案；逐条陈述绑定可核验原文 |
| 为什么让模型选择编号，而不直接复制引用？ | 模型可能删除链接或修改格式；服务器从原文单元还原，引用内容不由模型改写 |
| 答案不完整时怎样定位？ | 看原文是否含代码、正确片段是否召回、实际上下文是否过滤掉清理步骤；保留阈值并补齐授权证据 |
| 加相邻片段会绕过权限吗？ | 只从同一次已授权快照补齐；评测检查全部实际上下文，不仅检查最终引用 |
| 内容纠正和网络重试有什么区别？ | 已收到但无效的响应最多纠正一次并累计消耗；超时/429/500 不自动重试 |
| 引用存在能证明答案正确吗？ | 只能证明原文摘录存在；语义蕴含仍需人工或专门评测 |
| 为什么 BM25 比 Dense 更好？ | 技术标识符和直接术语匹配；需观察样本而非假定复杂模型总是更好 |
| 什么时候需要向量数据库？ | 量化每请求读快照、重建 BM25、全矩阵扫描的规模与延迟后再迁移 |
| 你具体做了什么，而开源做了什么？ | 对照 upstream-and-changes.md，准确归属算法和本次工程改造 |
| 项目最明显的欠缺是什么？ | 完整中文检索质量、独立留出集与第三方人类复核、较大规模性能、正式身份系统 |

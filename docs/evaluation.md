# 怎么定义成功，哪些数据可以引用

## 检索任务

问题：在用户可见资料里找出支持该问题的具体答案片段。

历史检索对照在 20 篇文档／323 个片段上运行；当前已补充两份代码，共 22 份资料／325 个片段。2026-10-12 已在当前语料上整体重跑四方案，报告另存。下文历史表保留原始数字，新结果见 `full-evaluation-20261012.md`。

输入为固定问题、同一可见文档快照、同一分块配置和固定模型权重。gold 包含文档 ID 与人工指定的原文摘录，只有片段包含该摘录才算命中。找到相同文件的无关段落不算成功。

32 个独立问题覆盖 20 篇官方资料，包括 4 个需要多个标注片段的问题；其中 2 个跨文档。所有问题均可回答，拒答和权限失败由独立边界测试检查，当前没有在此检索集上测拒答精确率。

指标：

- 证据覆盖率@5：每题在前 5 个片段中找齐的标注比例，再对题目取平均。
- Any-Gold@5：每题是否找到至少一个标注片段。
- All-Gold@5：每题是否找齐全部标注片段。
- MRR@5：第一个命中标注的片段排名的倒数，未命中记 0。
- 耗时：快照恢复、词表构建/召回、重排分开计时。热模型实验，另记首次预热耗时。

运行 eval.run_eval --repeat 3 得到 384 次检索运行。重复测的是时间波动；样本数量仍是 32，不能写“384 条标注问题”。四种模式在固定快照上执行；未调用生成模型、不评估最终答案正确性。

结果、原始每次排名、数据集与快照摘要、权重提交和环境信息保存在 reports/retrieval-comparison.json。热模型实验排除了数据入库和模型初次下载；不可将均值写成线上 P95。

## 实测如何解读

| 方案 | 覆盖率@5 | All-Gold@5 | MRR@5 | 平均热检索延迟 |
|---|---:|---:|---:|---:|
| Dense | 85.94% | 84.38% | 0.603 | 25.2 ms |
| BM25 | 93.75% | 90.63% | 0.774 | 22.9 ms |
| Hybrid | 90.63% | 87.50% | 0.743 | 25.8 ms |
| Hybrid + Rerank | 89.06% | 87.50% | 0.810 | 1235.3 ms |

技术术语让 BM25 基线很有竞争力。RRF 不保证好于任一路召回；Cross-Encoder 的更好首位排名需要额外推理时间。默认演示使用混合重排，页面可切换模式；没有宣称它在所有指标上最优。

纯向量到混合重排：MRR 增加 0.207（约 34.4% 相对提升），证据覆盖率增加 3.125 个百分点。相对 BM25，混合重排的覆盖率降低 4.6875 个百分点，MRR 增加约 0.0354。面试时同时说明对照与代价。

## 保留的失败样本

不要删除未命中的题或按这批结果重新选择标签，让分数变好。

| 案例 | 观察 | 后续调查方向 |
|---|---|---|
| Q001 后台任务执行时机 | BM25 命中标注，Dense / Hybrid / Rerank 未命中指定句子 | 阅读实际候选，检查同义证据、短答案段落和候选截断 |
| Q004 CORS origin 三要素 | BM25 / Hybrid 命中，Dense / Rerank 未命中 | 分析定义段落的召回及重排排序 |
| Q020 可选参数判定 | 四模式均未命中 body 文件里的指定说明 | 检查查询参数文档的等价说明；补充标签需人工复核，不能直接视为答案错误 |
| Q021 yield 数据库资源清理 | 四模式仅找到一半标注 | 一个题需要同时找到用途与具体 yield 方法 |
| Q032 workers + WebSocket 多进程限制 | 重排找齐两篇标注，其他模式未全部找到 | 多文档证据覆盖与首位相关性是不同目标 |

当前标注可能没有穷尽所有等价答案位置。“未命中指定 gold”不必然意味着最终回答错误。下一步应让另一位标注者审核可替代证据，并新增独立留出集；目前是小规模开发集，不推断泛化能力。

## 边界与执行测试

人工审核机制加入后 76 项 pytest 测试通过，组件替身只服务于逻辑断言，不参加真实模型对照：

- 同一资料重传时不重复算向量，更新后没有旧片段，删除级联清理。
- 向量计算失败、NaN 或模型变化时拒绝破坏原版本。
- 四模式均在权限过滤后召回；部门和租户隔离，管理员也不能越租户。
- 客户端正文的 admin/tenant 被拒绝；普通读者不能写入。
- 引用 ID 越界、假摘录、空白摘录、自造标号均拒绝。
- 仅把实际使用且校验通过的引用返回，证据为空时拒答。
- 并行请求各自保留 top_k，不修改共享参数。
- 真实兼容 SDK 通过 MockTransport 验证 JSON 协议、usage 与失败处理。
- 超时、连接、429 和 500 分类；SDK 零自动重试，失败后释放并发名额，满额快速拒绝。
- 模型只选择编号，程序还原原文；正文语言、最多两次生成及累计消耗符合约定。
- 上下文扩展继续受权限约束；即使私有片段没有被模型引用，进入实际上下文也判权限失败。

本次测试修复的实际问题：单篇可见文档下原 BM25Okapi 的 IDF 可能为负，正分筛选会遗漏关键词命中。改成 log(1 + (N-df+0.5)/(df+0.5)) 平滑 IDF，保留同一回归测试验证四模式。这个修改并非模型调参或训练。

## 真实生成任务

输入问题 → 可见证据 → LLM 生成结构化陈述 → 程序核验引用 → 人工对原文核对内容。

eval.run_answers --limit 5 在配置 compatible 模式后才调用真实 API。结果保存完整答案、引用、真实 Token、延迟、失败与待填写的人工审核字段。异常案例仍保留在分母中，不静默删除。

人工成功标准是：回答解决问题，所有关键陈述被证据支持，来源适用且身份有权限；资料不足时应明确说明。不能仅因为 JSON 可解析或引用存在，就判为端到端成功。

已使用 deepseek-chat 执行 50 题主评测与 6 道相近主题拒答题。主集包括正常问答 32 题、无答案 6 题、错误前提 6 题、权限边界 6 题。主集 39 次请求与补充集 6 次请求返回真实 API usage；其余主集题在无证据时由应用拒答，不产生模型调用。

Codex 按陈述与引用逐题复核，主集完整任务通过 43/50；这个标准包含回答完整性与语言一致性。独立人类审核字段尚未填写，不能把助手复核称为人工标注准确率。Q001、Q020 的等价证据通过语义复核；Q004 召回不足、Q005/Q028 引用失败、Q021 答案不完整，以及三道语言错误均保留。详细记录见 validation-results.md。

弱相关余弦阈值 0.35 是演示配置，尚未通过独立正/负样本集校准；它不能保证所有越界问题都拒答。API 生成模型是服务商别名，不能像本地权重一样声称固定了生成模型的内部版本。

七个原失败场景分别运行两次，共 14 次真实请求。检查问题是否完整回答、实际引用是否支持关键陈述、输出语言是否符合要求，助手按证据复核 14/14 达到预期。它们仍是七道独立问题。

保留旧协议复现、两轮失败中间结果和标注修订前的数据。新十二题最终协议允许每条最多八个引用；三引用版本通过记录另存。源位置修订没有改变问题或预期行为。详情及复现方法见 `answer-repairs.md`。

这些是开发回归，不是独立留出评测；没有将历史 43/50 改成全量 100%。中文题包含明确技术标识符，不构成全面中文语义检索测评。

## 修复版全量与人工复核

原 50 题在相同题目和预期标准下已全量重跑，39 题回答、11 题拒答、没有运行错误，自动状态和权限检查全部通过。11 个拒答分别是六个无答案问题和五个权限问题；32 道正常题均返回回答。拒答是否合理仍需按资料和身份复核，不能看到拒答就判错，也不能仅因类型是拒答就判对。

完整任务的语义正确率尚未用真实人工记录计算。用户选择作者本人逐题评分，工作台默认隐藏 AI 评分，中文译文只辅助阅读，原始英文回答保持冻结。来源摘要和人工记录分开，未评分不补写为通过。作者人工审核不是第三方独立审核，当前数据也不是盲测。

当前 22 份资料的四方案对照完整运行 32×4×3 次。与补充资料前相比，正确片段位置可能变化；这次混合重排 MRR 为 0.810，BM25 的覆盖率仍最高。检索与生成程序同机有重叠，耗时只作为该次观察。新报告和人工操作见 `full-evaluation-20261012.md`、`manual-review-guide.md`。

## 稳定性与恢复

本机摘录模式 36 次热请求、真实生成 12 次热请求，分别测 1/2/4 并发。它们只验证该轮请求是否完成及来源/参数边界，不代替逐题正确性评审。P50/P95 包含 HTTP 墙钟时间；进程首请求、热请求分开报告，已有本地模型缓存。

本机故障上游按顺序注入读取超时、429、500 和正常响应。真实 SDK 与真实 HTTP 服务返回对应的分类 503，第四请求成功；只出现四次上游请求。SDK timeout 作用于网络阶段，不包含本地检索和重排，不能把它当成整条请求的全局截止时间。

# 为什么选这个项目，哪些是自己做的

选用 [Pasukalu/rag-qa-system](https://github.com/Pasukalu/rag-qa-system)。它规模较小，已有完整的检索到回答结构，也有 MIT 许可证，方便逐函数理解。比直接使用大型知识库产品更适合解释具体决策和失败原因。

保留原始 README.upstream.md、LICENSE 和 UPSTREAM.json。所有“上游”判断基于固定提交 9dd2eb16bfeeb9f483b87490805ed18cdd5bc979 的源码，不把其 README 中未复核的宣传数据当成事实。

## 对照岗位与简历

[北京众智诚坚技术岗位页面](https://jobs.tiangong.edu.cn/correcruit/content/id/55660.html) 涉及文档处理、检索、重排、评测及 Python 工程；[百度 Agent 应用实习岗位](https://talent.baidu.com/jobs/detail/INTERN/e3cec5b8-b7a3-4946-99fc-b292b749cd53) 提到 RAG、Agent 框架和问题定位。这只是具体岗位参考，不能推断所有北京公司的录用标准。

之前的 [30 份公开简历对照](../../../docs/resume-benchmark-30-20261011.md) 中，Ahmed Doghri 的混合检索与引用质量、Sam Latino 的 BM25 基线评测、Deepak Silaych 的前后对照值得借鉴。公开简历中的数字无法独立核验；本项目只报告自己的运行记录。样本以海外公开简历为主，并不代表北京实习候选人的平均水平。

因此本次集中补强可解释的工程边界与对照实验，不复刻一串流行技术名词。

## 贡献边界

| 模块 | 上游已有 | 本次改造 |
|---|---|---|
| 编排 | chunk → embedding → hybrid → rerank → generation | 保留组件结构，改为权限快照与请求内参数 |
| 检索 | BM25 + 向量 + RRF | 技术词分词、正 IDF 小语料边界、四模式、真实余弦分数 |
| 本地模型 | SentenceTransformer / CrossEncoder | FastEmbed / ONNX，固定权重提交，CPU 可复现 |
| 文档持久化 | NumPy 文件 + 简单元数据 | SQLite 原文、版本、向量、ACL；摘要跳过与事务替换 |
| 分块 | 按句子、字符大小分块 | 标题、代码围栏识别、完整行重叠、原始行号、稳定片段 ID |
| 引用 | 生成后返回所有上下文 ID | 模型选择原文单元编号，服务端还原摘录；校验 ID、正文语言和预算，只列使用的引用 |
| 上下文 | 原召回片段 | 同一权限快照内补充技术标识符命中、相邻说明及两份固定版本代码，记录选择原因 |
| 接口 | FastAPI 问答、全局 pipeline、共享 top_k | app.state、服务端令牌绑定身份、输入约束、管理写权限 |
| 评测 | 原示例 20 题、来源命中、词语重合代理指标 | 32 题答案段落标注、固定快照、四路重复对照及边界测试 |
| 界面 | 简单问答页 | 文档范围、可展开引用、行号、阶段耗时 |
| 消耗 | 累计计数、默认价格估计 | 单请求真实 API usage，价格未配置就不生成金额 |

上游原始示例 data/sample_docs 与 eval/golden_set.json 保留供参考，新流程只读取 data/corpus 与 eval/tech_qa.json。不再沿用上游“词语重合 = 忠实度”或据此判断幻觉的口径。

## 为什么没有上复杂组件

当前仅 325 个片段，向量在 NumPy 快照内做余弦检索即可。SQLite 负责持久化与筛选，不是向量数据库。达到更大规模后，应量化每请求建 BM25、扫描向量和读快照的成本，再决定迁移 Qdrant、pgvector 或搜索引擎。

默认模型基于英文；中文分词的存在不等于中文语义模型已经可靠。已补充两份固定版本代码并验证含标识符的中英文题，完整中文语义检索、PDF/OCR、全部代码 include 补全、企业 SSO 和跨进程任务队列尚未完成，应作为后续路线。实际修复与回归见 `answer-repairs.md`。

## 与已有工单 Agent 的组合

工单项目展示持续会话、业务状态与有副作用工具的可靠执行。本项目展示知识处理、检索对照、资料可见性和引用追溯。面试中分别说明自己负责的实现、真实失败案例和测量口径，避免两段项目都只介绍“调用大模型回答问题”。

# 失败定位、修复方法与验证

后续已完成修复版 50 题和当前语料四方案的全量重跑，见 `full-evaluation-20261012.md`。本文保留修复阶段记录和当时的验证范围，人工分数以独立的真实评分文件为准。

本次处理原评测中的七个失败场景：两题引用／格式失败、一题答案不完整、三题语言错误，以及一题漏掉定义段落。修改了实际检索、上下文构造和生成代码。

修复前的 50 题记录保留在 `reports/answer-review.json`，完整任务通过 43/50。这次是针对失败的回归和新增开发验证，不能把回归通过率替换成整个项目的准确率。

## 一、先确认失败发生在哪一层

排查顺序是：原文是否完整 → 正确片段是否召回 → 哪些片段实际送给模型 → 模型返回什么 → 哪个校验条件拒绝了它。只看最终一句“引用无效”，无法区分检索问题和输出格式问题。

| 场景 | 原来表现 | 定位结果 | 已完成的修改 |
|---|---|---|---|
| Q005：CORS 凭据与通配符 | 有资料，仍因引用无效而拒答 | 用旧提示词和原证据重新调用模型，3 次中 1 次把引用中的 Markdown 链接改成普通文字；含义近似，但不再是原文子串 | 模型只选择片段编号和原文单元编号，程序还原原文，保留链接、反引号等格式 |
| Q028：创建 TestClient | 有正确步骤，结构校验失败 | 旧协议复现 3 次，均输出 9 条陈述，超过校验器的 6 条限制；提示词没有说明这个限制 | 提示词与校验器写明相同预算；优先 1～3 条聚焦陈述；补充真实代码示例 |
| Q021：yield 后关闭数据库 | 只解释大致作用，没有完整清理步骤 | 含 `finally` 的片段余弦分数约 0.326，被 0.35 阈值过滤；另一段虽然提到示例，但只保存了代码 include 占位符，实际代码没有入库 | 补充固定版本的官方 `get_db` 代码；在同一授权快照内补齐相邻片段和引用代码 |
| Q008、Q023、F004：回答语言 | 英文问题得到西班牙语或中文答案 | 应用没有确定输出语言，也没有检查正文语言；引用校验不检查语言 | 应用确定 en/zh，传给模型，再用本地识别检查正文；错误时最多纠正一次 |
| Q004：origin 的定义 | 召回相关资料，却缺少协议、域名、端口的定义 | 前五个候选及弱相关筛选没有留下定义段落 | 从可靠锚点补齐同一文档的前后相邻片段，并记录补充原因 |

**证据边界：**历史 Q005、Q028 的失败草稿没有保存，不能恢复其当时的精确错误。表中的具体引用／格式原因来自本次六次真实旧协议复现，完整响应见 `reports/legacy-citation-replay.json`。它证明了可复现的故障机制，不代表找回了历史原始响应。

## 二、引用改成“选择编号，再还原原文”

原来让模型同时完成两件事：写答案，以及逐字复制原文。复制时删掉链接、改动空白或输出过多陈述，都可能把有价值的回答变成格式失败。

现在先由程序把证据切成原文单元，每个单元保留精确子串。模型返回下面的结构：

```json
{
  "language": "en",
  "claims": [
    {
      "text": "A supported statement.",
      "evidence": [{"id": 1, "span_id": 2}]
    }
  ]
}
```

`id` 是本次请求的证据片段编号，`span_id` 是片段内的原文单元编号。模型不能提交 `quote`。`resolve_references()` 检查编号，再从服务端已有单元中还原摘录，随后 `validate_draft()` 继续检查引用范围、原文子串和答案中的自造引用标号。

预算仍然明确：最多 6 条陈述，每条最多 8 个引用，每条文字最多 1500 字符，每个摘录最多 800 字符。细粒度切分后，一条完整的操作说明可能需要多段证据。开发中曾保留旧的“每条 3 个引用”限制，导致 TestClient 的 4～5 个有效引用被误拒；已保留失败记录，调整为 8 个，并测试 4 个合法引用通过、9 个引用被拒。

这保证引用来自本次真实证据；**没有自动证明“证据必然支持答案含义”**。模型选择错误段落或根据真实段落作出过度推断，仍需内容评审。

相关函数在 `app/rag/generation.py` 和 `app/rag/evidence.py`，每个函数及其内部调用见 `docs/functions.md`。

## 三、补齐证据，不靠全局降低门槛

本次保持余弦阈值 0.35。上下文最多 8 个片段，全部来自当前身份已经过滤过的同一个资料快照：

1. 对问题中明确出现的 `get_db`、`TestClient`、`yield`、`finally` 等代码标识符，精确匹配可见资料，最多补 2 个片段。普通词不触发这条通道。
2. 保留检索结果中达到原有相关性条件的片段，作为证据锚点。
3. 从前两个用于扩展的锚点，查找已入库的本地代码示例和同一文档前后紧邻片段。
4. 按文档、片段位置和版本去重，到达预算就停止。

新增 `context_selection` 记录每个片段为什么被加入：精确标识符、可靠锚点、引用代码或相邻说明。原始 `retrieved` 和实际模型 `context` 分开保存，便于看清“检索找到”与“模型看到”的差别；补充资料不伪造向量或重排分数。

还增加评测检查：即使模型没有在最终答案引用某份私有资料，只要它进入了实际上下文，也算权限失败。公开资料指向私有代码时，不能绕过快照权限补全。

两个代码文件来自与文档相同的 FastAPI 固定提交 `f5c6e9b4f9cadc1bf0f9a1fd672e621206b63007`：

- `docs_src/dependencies/tutorial007_py310.py`：`DBSession()`、`yield db`、`finally: db.close()`。
- `docs_src/app_testing/tutorial001_py310.py`：创建 FastAPI 应用、`TestClient(app)` 与普通测试函数。

下载核对 Git Blob 和 SHA-256，原样保存在 `data/corpus/`，清单保存来源、版本、许可证和权限。它们是知识资料，不是需要执行的项目业务模块。引用代码时展示代码文件自己的真实行号，不把代码伪装成 Markdown 文件中的某一行。

当前语料为 **20 篇文档 + 2 份代码示例，合计 22 份资料、325 个片段**；读者可见 19 份，运维身份可见 22 份。只补了这两份相关示例，尚未自动补全所有 include。

标识符通道同时解决了新增中文题中“英文向量模型无法达到相关性阈值”的一个局部问题。但它不等于完成中文语义检索；没有显式标识符的中文问题仍可能漏召回。

## 四、语言检查和有限纠正

HTTP 参数 `answer_language` 支持 `auto`、`en`、`zh`。自动模式对含至少两个中文字符的问题选择中文，其他问题选择英文；调用者也可以显式指定。

生成提示明确要求目标语言。程序还检查模型声明的 `language` 和实际回答正文，移除代码及 URL 后，用本地语言识别判断。正文很短、只有技术表达时记为“不确定”，不会伪造一个高置信度的语言通过结论。中文／英文之外的输出语言目前不支持。

如果已经收到了模型响应，但格式、编号或语言不符合要求，应用最多再请求一次，用原证据和固定诊断码要求纠正。两次仍失败就拒答，不展示未通过校验的草稿；Token 统计累计两次响应。

**这与网络重试不同。**SDK 自动重试仍为零。超时、连接失败、429 或 500 继续直接返回分类故障，不启动内容纠正。因此纠正次数和额外消耗可控，但有纠正的请求仍可能比一次生成更慢、更贵。

细分诊断包括 `INVALID_SCHEMA`、`SPAN_ID_OUT_OF_RANGE`、`QUOTE_NOT_IN_EVIDENCE`、`LANGUAGE_MISMATCH`、`TRUNCATED_RESPONSE` 等。评测可以记录被拒草稿；日常 HTTP 接口没有这个诊断回调，也不把草稿作为用户成功回答。

上述内容复核由 Codex 完成，**不是独立人类标注，也不是盲测**。原 50 题没有整体重跑，不能宣称“准确率从 86% 提升到 100%”。新增资料与生成协议同时变化，这次结果也不能拆成单个算法的独立提升幅度。原 20 篇／323 片段上的检索对照和并发数据继续保留为历史基线，没有冒充修复版的全量实测。

新题中部分回答仍比问题需要的范围更长，例如 TestClient 的函数类型问题附带了额外使用步骤。其内容有引用支持、主问题得到回答，但“优先 1～3 条陈述”仍是提示要求，不是已经证明稳定达到的简洁性指标。

容器检查是在本机临时 Linux ARM64 环境完成，尚未公网发布，也不证明 amd64 或另一台物理服务器已验证。临时容器测试环境已经停止。

## 七、面试时怎样解释

可以这样讲：我先把端到端失败拆成资料、检索、实际上下文和输出校验四层。定位到模型改写引用、提示词与结构预算不一致，以及代码示例未入库造成答案不完整。随后把引用复制改为编号选择和程序还原，在授权快照内补齐代码与相邻证据，并增加应用语言检查和最多一次内容纠正。保留中间失败，最终七个失败场景各验证两次，同时加入十二道中英文、无答案及权限题。所有数字注明开发集和复核方式，不把回归成功说成整体准确率。

后续最需要的改进是：另一位标注者的独立复核、未参与开发的留出题集、更大范围的代码 include 导入和中文检索评测。是否更换多语向量模型，应在同样的评测条件下比较召回、耗时与代价后决定。
